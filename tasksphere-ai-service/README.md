# TaskSphere – AI Service (FastAPI / Python)

This is the AI/ML microservice from the TaskSphere architecture. It's called
server-to-server by the Spring Boot core application whenever a task is
created or updated — the React frontend never talks to this service directly.

## What it does
Two trained scikit-learn models:

1. **Category classifier** — TF-IDF (title + description, 1-2 grams) → calibrated LinearSVC.
   Predicts one of 10 categories: Bug Fix, Feature Development, Documentation,
   Testing, Design, DevOps/Infrastructure, Research, Meeting/Admin, Maintenance, Security.

2. **Priority predictor** — TF-IDF text features + `days_until_due` (scaled) → LogisticRegression.
   Predicts LOW / MEDIUM / HIGH / URGENT, plus a continuous `priority_score` (0-1)
   computed as a probability-weighted average across the four classes (so it reflects
   model confidence, not just the winning label).

Both were trained on `ml/data/tasks_training_data.csv`, a **synthetic** dataset
(3,000 rows) generated by `ml/generate_dataset.py` using templated task phrasing,
randomized urgency language, and randomized due-date proximity — see the "Replacing
with real data" section below for how to swap in your team's actual task history.

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| GET | `/health` | Liveness + model-loaded check |
| POST | `/api/ai/analyze-task` | **Main endpoint.** Called by `AiClientService.java` on task create/update. Returns category + priority together. |
| POST | `/api/ai/classify` | Category only (e.g. for live-typing suggestions in the UI) |
| POST | `/api/ai/recommend` | Category + priority + a few rule-based next-step tips |

`/api/ai/analyze-task` request/response (matches what the Spring backend already sends/expects):
```json
// POST /api/ai/analyze-task
{ "title": "Fix crash on checkout", "description": "Prod is down, urgent.", "due_date": "2026-08-14" }

// Response
{
  "suggested_category": "Bug Fix",
  "category_confidence": 0.847,
  "priority_score": 0.9088,
  "suggested_priority": "URGENT",
  "priority_confidence": 0.9405
}
```

Interactive API docs are auto-generated at `/docs` (Swagger UI) once the server is running.

## Running locally

```bash
cd tasksphere-ai-service
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

# Train the models (only needed once, or whenever you change the training data)
python ml/generate_dataset.py
python ml/train_model.py

# Start the API
uvicorn app.main:app --reload --port 8000
```

Then visit `http://localhost:8000/docs` to try it interactively, or:
```bash
curl -X POST http://localhost:8000/api/ai/analyze-task \
  -H "Content-Type: application/json" \
  -d '{"title":"Fix crash on checkout","description":"Prod is down, urgent.","due_date":"2026-08-14"}'
```

## Wiring it to the Spring Boot backend
Set `AI_SERVICE_URL=http://localhost:8000` (or wherever this service runs) as an
env var on the Spring Boot app. `AiClientService.java` already calls
`POST {ai-service.base-url}/api/ai/analyze-task` on every task creation and reads
`suggested_category` / `priority_score` from the response — no backend changes needed.

## Model quality note
On the held-out test split, both models score ~100% accuracy. That's expected and
somewhat artificial: the synthetic generator uses a fixed set of phrase templates per
category/priority, so the text patterns are highly learnable. It's a solid proof of
the pipeline (feature engineering, training, serving, the Java↔Python contract) —
**retrain on real historical task data before trusting this in production**, and
expect real accuracy to land lower (validate with a proper train/test split on your
own labeled tasks).

## Replacing with real data
1. Export your team's actual tasks as CSV with columns: `title, description, category,
   priority, days_until_due` (category/priority = the label a human actually chose).
2. Point `ml/train_model.py`'s `DATA_PATH` at that file instead of the generated one.
3. Re-run `python ml/train_model.py` — it retrains and overwrites both `.joblib` files.
4. Restart the API (`uvicorn ...`) so it picks up the newly trained models.
